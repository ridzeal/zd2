## Phase 2 — Adventurer Arrival & Wander

**Goal:** Adventurers arrive after milestones (day threshold or events), wander between rooms, idle animation visible.

**Deliverable:** Watch adventurers roam the village after reaching a milestone — no economy tie-in yet.

**Key design decision:** Adventurers don't "spawn" periodically — they arrive as visitors after the village reaches certain milestones (e.g., Day 3: first visitor, Day 7: second wave, etc.). This feels more like a village simulation than a dungeon spawner.

**Note:** The `src/systems/` directory is created here with SpawnSystem and AISystem as separate files (per user preference).

### Files to Create

| File | Purpose |
|------|---------|
| `src/data/classes.json` | Adventurer class definitions (warrior, mage, thief, cleric) with baseStats + spawnWeight + unlockLevel |
| `src/data/milestones.json` | Milestone thresholds for adventurer arrivals (day → count) |
| `src/entities/Adventurer.ts` | Adventurer class: movement, rendering, state machine (idle → walking → idle) |
| `src/systems/SpawnSystem.ts` | Milestone-based adventurer arrival: checks day thresholds, triggers weighted class selection |
| `src/systems/AISystem.ts` | Wander behavior: pick random room target, walk, idle, repeat |

### Files to Modify

| File | Change |
|------|--------|
| `src/core/GameState.ts` | Add `reachedMilestones: number[]` to GameState; expand AdventurerInstance with `targetX`, `targetY`, `state`, `name` fields |
| `src/core/EventBus.ts` | Add events: `adventurer-arrived`, `adventurer-removed`, `milestone-reached` |
| `src/core/TickEngine.ts` | Call SpawnSystem.process() + AISystem.process() on each tick |
| `src/scenes/WorldScene.ts` | Render adventurers as colored circles with name labels; call Adventurer.update() each frame |
| `src/main.ts` | Wire SpawnSystem + AISystem into TickEngine |

### Implementation Details

**1. `src/data/classes.json`**
```json
[
  { "id": "warrior", "name": "Warrior", "baseStats": { "atk": 10, "def": 8, "hp": 30 }, "spawnWeight": 40, "color": "#e74c3c", "unlockLevel": 1 },
  { "id": "mage", "name": "Mage", "baseStats": { "atk": 14, "def": 3, "hp": 20 }, "spawnWeight": 25, "color": "#3498db", "unlockLevel": 1 },
  { "id": "thief", "name": "Thief", "baseStats": { "atk": 8, "def": 5, "hp": 25 }, "spawnWeight": 25, "color": "#2ecc71", "unlockLevel": 1 },
  { "id": "cleric", "name": "Cleric", "baseStats": { "atk": 6, "def": 6, "hp": 28 }, "spawnWeight": 10, "color": "#f39c12", "unlockLevel": 1 }
]
```
Note: `unlockLevel` field added for Phase 4 progression gating. All base classes unlock at level 1.

**2. `src/entities/Adventurer.ts`**
- Class wrapping AdventurerInstance data
- `update(dt)` — move toward targetX/targetY at fixed speed (pixels per tick)
- `render(graphics)` — draw as colored circle with small hp bar + name label
- State: `'idle'` | `'walking'`
- When reaching target, set state to idle
- Name label: show class name (e.g., "Warrior") above adventurer circle
- HP bar: small bar below circle, green when full, red when low

**3. `src/systems/SpawnSystem.ts` — Milestone-based arrival**
- Load milestones from `src/data/milestones.json`: e.g., `[{day: 3, count: 1}, {day: 7, count: 2}, {day: 14, count: 3}]`
- On each tick, check if current day crosses a milestone not yet in `GameState.reachedMilestones`
- If milestone reached: spawn `count` adventurers (weighted random from classes.json)
- Spawn point: center of a random room grid cell (prefer entrance if placed)
- Max adventurer cap: 20
- Emit `milestone-reached` and `adventurer-arrived` events
- One-time trigger per milestone, not periodic
- Track reached milestones in `GameState.reachedMilestones: number[]`
- Check: `state.day >= m.day && !reachedMilestones.includes(m.day)`
- Edge case: no rooms → skip (need rooms to wander)

**4. `src/systems/AISystem.ts` — Wander behavior**
- For each adventurer in `'idle'` state:
  - Pick a random room as target (weighted by room `attract` value if available)
  - Set state to `'walking'`, calculate target pixel position from room's grid coords
- For each adventurer in `'walking'` state:
  - Move toward targetX/targetY at fixed speed
  - On arrival: set state to `'idle'`, wait idleTime ticks, then pick new target
- Clamp movement to grid bounds
- Note: Adventurers start at entrance or random room if no entrance placed
- Movement: simple linear interpolation, no pathfinding needed for MVP grid
- Constants: `WALK_SPEED = 2` px/tick, `MIN_IDLE = 20`, `MAX_IDLE = 50` ticks
- Target: cell center `(gridX * 32 + 16, gridY * 32 + 16)` where GRID_SIZE=32

**5. WorldScene rendering**
- After room redraw, iterate `gameState.adventurers`
- Call `adventurer.update()` then `adventurer.render(graphics)`
- Circle + small hp bar + name label for MVP visuals
- Name: class name above circle
- Render order: rooms first, then adventurers (no depth sorting yet)
- Constants: `RADIUS = 8`, HP bar: 16×2 px, text: 10px monospace white
- Colors: from classes.json definition
- HP bar: green when full, red when below 30%

### Test Plan
- `tests/spawn.test.ts`: SpawnSystem triggers at correct day milestones, respects max cap, weighted class selection
- `tests/ai.test.ts`: Adventurer reaches target, picks new target after idle
- Manual: Place a few rooms, advance days to milestone thresholds, watch adventurers arrive and walk around

### Dependencies
- None (builds on Phase 0+1)

## Phase 3 — Core Economy Loop

**Goal:** Adventurers interact with rooms (income/heal/stock effects), quest/dungeon delves resolve, full gold loop closes.

**Deliverable:** Build room → adventurers generate gold via income effect → gold funds more rooms. "It's a game now."

**Note:** Room gold generation uses the `income` effect type in rooms.json (e.g., shop effect: `{type:'income', value:5}`). This keeps room definitions data-driven and easy to balance.

### Files to Create

| File | Purpose |
|------|---------|
| `src/systems/EconomySystem.ts` | Processes room interactions based on effect type: income=gold gen, heal=HP restore, stock=buff |
| `src/systems/QuestSystem.ts` | Auto-battle formula: adventurer stats + room bonuses vs dungeon difficulty → loot/gold |
| `src/data/lootTables.json` | Loot drop tables per dungeon difficulty tier |

### Files to Modify

| File | Change |
|------|--------|
| `src/core/GameState.ts` | Add `exp`, `maxAdventurers` to GameState; add Adventurer fields: `state: 'idle'|'walking'|'shopping'|'healing'|'questing'`, `questCooldown`, `gold` (personal gold from quests) |
| `src/core/EventBus.ts` | Add events: `room-interaction`, `quest-complete`, `loot-drop`, `xp-gained` |
| `src/core/TickEngine.ts` | Call EconomySystem.process() and QuestSystem.process() on each tick |
| `src/scenes/WorldScene.ts` | Visual feedback for interactions (floating text on gold earn/spend) |
| `src/data/rooms.json` | Add `income` effect type to rooms (e.g., shop: `{type:'income', value:5}`) |

### Implementation Details

**1. EconomySystem.process(state, tick)**
- For each adventurer in `'idle'` state at a room:
  - Read room's `effect` field from rooms.json
  - If `effect.type === 'income'`: village earns `effect.value` gold, adventurer pays same amount
  - If `effect.type === 'heal'`: adventurer restores `effect.value` HP per tick while at inn
  - If `effect.type === 'stock'`: adventurer gets buff (ATK/DEF) proportional to `effect.value`
  - If `effect.type === 'attract'`: no direct interaction, but increases spawn rate (already handled in SpawnSystem)
  - Each interaction has a cooldown (e.g., 30 ticks)
- Emit `room-interaction` event for floating text with effect type info

**2. QuestSystem.process(state, tick)**
- Adventurers at Dungeon Entrance auto-queue for quest
- After short delay, resolve quest:
  - Win chance = `(adventurer.atk + adventurer.def) / (dungeon_difficulty * 2)`
  - On win: drop loot from lootTables.json, adventurer gains XP, village earns gold tax
  - On loss: adventurer loses HP, returns to inn to heal
- Emit `quest-complete`, `loot-drop`, `xp-gained`

**Note:** Higher-tier adventurer classes unlock at specific levels, not milestones. This adds progression depth beyond the initial milestone-based arrivals.

### Files to Create

### Files to Modify

### Implementation Details

**1. Level system**

- Max level cap for MVP: 5

**2. Speed toggle**
- Simple 1x/2x button in bottom-right of UIScene
- Calls `tickEngine.setSpeed()` on click

**3. Build menu filtering**
- Rooms with `unlockLevel > gameState.level` shown grayed out with lock icon

**4. Higher-level content**

## Phase 5 — HD-2D Visual Pass

**Goal:** Replace placeholder rects with generated pixel sprites, add depth-sorting, bloom/DOF/vignette.

**Deliverable:** Same Phase 4 loop, now visually in target HD-2D style with clear placeholder sprites.

**Note:** Generated sprites use clear silhouettes and colors per room type and adventurer class. These are placeholders — user will replace with final pixel art later.

### Files to Create

### Files to Modify

| File | Change |

| `src/main.ts` | Add postFX pipeline to camera |
| `src/data/rooms.json` | Add `sprite` field pointing to sprite key |

### Implementation Details

**1. Sprite-based rendering**
- Generate clear placeholder pixel art (16×16 or 32×32) that's distinct per room type and adventurer class
- Use colored shapes with clear silhouettes (e.g., shop = house shape, inn = bed shape, warrior = sword silhouette)
- Rooms: static sprite per type
- Adventurers: each class gets a walking animation (2–4 frames) + idle frame
- Use Phaser Sprite instead of Graphics.fillRect
- Note: These are placeholders — user will replace with final pixel art later

**2. Depth sorting**
- Sort all sprites by Y position each frame
- `sprite.setDepth(sprite.y)` for proper overlap

**3. HD-2D post-processing**
- **Bloom**: Phaser's built-in PostFX bloom on bright elements
- **DOF**: Gaussian blur on far edges (or simplified vignette blur)
- **Vignette**: Dark edges overlay
- **Color grading**: Warm tint, slight saturation boost
- Apply via Phaser's `camera.postFX` pipeline

**4. Animated sprites**
- Adventurers: idle bob, walk cycle (use Phaser sprite sheets or tween-based)
- Rooms: subtle animation (shop sign swing, inn chimney smoke)

## Phase 6 — Save/Load + Polish

**Goal:** Single-slot localStorage save/load, UI polish, sound stubs.

**Deliverable:** Close browser, reopen, session restores with all milestone-based adventurer arrivals intact. MVP-complete.

**Note:** Save system must persist milestone state (which milestones have been reached) so adventurer arrivals don't re-trigger on load.

### Files to Create

| File | Purpose |
|------|---------|
| `src/core/SaveSystem.ts` | Serialize/deserialize GameState to localStorage |
| `src/ui/SaveLoadUI.ts` | Save/Load buttons in UIScene |

### Files to Modify

| File | Change |
|------|--------|
| `src/core/GameState.ts` | Add `toJSON()` and `fromJSON()` methods or standalone serializer |
| `src/scenes/UIScene.ts` | Host SaveLoadUI |
| `src/main.ts` | Auto-load on boot; save on page unload |
| `src/ui/BuildMenu.ts` | Polish: cost color coding (red if can't afford), hover tooltips |
| `src/scenes/WorldScene.ts` | Polish: room placement animation, adventurer spawn effect |

### Implementation Details

**1. Save/Load system**
- `SaveSystem.save(state)`: JSON.stringify gameState → localStorage key `'zd2-save'`
- `SaveSystem.load(): GameState | null`: JSON.parse from localStorage
- Auto-save every 60 seconds + on `beforeunload`
- Load on boot in BootScene, replace gameState singleton

**2. Serialization considerations**
- AdventurerInstance: all fields are primitives (string, number) — trivially serializable
- PlacedRoom: same — primitives only
- Milestone state: track which milestones have been reached (boolean array or Set)
- Strip any Phaser-specific references before save

**3. UI polish**
- Build menu: red cost text when can't afford, green when can
- Room placement: brief scale tween on placement
- Adventurer spawn: fade-in effect
- Gold change: floating +/- text with tween
- Day change: brief screen flash or notification

**4. Sound stubs**
- Placeholder audio files for: room placement, gold earn, quest complete, level up
- Use Phaser sound manager with stub/silent audio
- Volume toggle in UI (optional for MVP)

### Test Plan
- `tests/save.test.ts`: Save/load roundtrip, handles missing save gracefully
- Manual: Play, save, close tab, reopen, verify state restored
- Manual: UI polish — tooltips, animations, floating text all work
